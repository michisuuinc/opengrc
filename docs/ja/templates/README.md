# Pマーク・個人情報保護の文書ひな形

Pマーク（JIS Q 15001:2023、JIPDEC 構築・運用指針）の運用に必要な方針・規程・手順・公表文・書式のひな形です。自社の実態に合わせて書き換え、代表者などの承認を得てから使ってください。

- **独自の文章**：JIS Q 15001 や JIPDEC の指針の本文は転載していません。要求事項の詳細は、必ず原文で確認してください。
- **法令の基準日**：2026-10-14 時点で施行されている個人情報保護法に基づいています。2026 年に成立・公布された改正法（課徴金制度の導入など）は施行前で、施行時に見直しが必要な箇所には「改正法の施行時に見直す」と注記しています。
- **審査項目との対応**：各文書の冒頭に、対応する J 番号（JIPDEC 構築・運用指針の項番）を書いています。このリポジトリの Pマークのフレームワーク（`apps/console/public/data/frameworks/jp/`）と内部統制（`apps/console/public/data/internal-controls/jp/`）と同じ番号です。

## 使い方

1. **完成版を作る**：会社名や管理者などを設定ファイル（YAML）に書き、生成ツールで 18 本の完成版を作ります。手順と項目の一覧は [variables.md](variables.md) を、設定ファイルの例は [config.example.yaml](config.example.yaml) を見てください。

   ```sh
   go run ./cmd/ja-docgen -config ../社内/自社.yaml -out ../社内/完成版
   ```

   第三者提供や共同利用をするかどうかなどの選択に合わせて、必要な節だけが残ります。「※」で始まる作成者向けの注記は、完成版では削除されます。ツールを使わずに手で書き換える場合は、ひな形の【 】を置き換え、`<!-- if … -->` などの指示と「※」の注記を削除してください。
2. 完成版の内容が自社の実態に合っているかを確認し、必要なら書き換えます。
3. 完成版を OpenGRC に登録し、フレームワークと内部統制に紐付けます（`node scripts/ja-docs/sync.mjs`）。文書の種類は下の表の「画面での種類」で登録されます。手順は [利用マニュアルの文書編](../manual/02-documents.md) を見てください。
4. 承認の流れに回し、承認後に公開します。従業者に署名を求める文書（方針、規程など）は、従業員ポータルで署名を集めます。

自社の値を入れた設定ファイルと完成版は、このリポジトリの外（社内の private リポジトリなど）に置いてください。ツールは、このリポジトリの中の設定ファイル（設定例を除く）や出力先を受け付けません。

## 書き方のルール（ひな形を直すときも守る）

- **置き換える部分**：【会社名】【記録の保存期間】のように、全角の【 】で囲む。使える変数は [variables.md](variables.md) の一覧にあるものだけで、新しい変数は `cmd/ja-docgen/schema.go` に追加する。同じ意味のものは、すべての文書で同じ変数にする。書式を使うたびに書く欄は【記入：委託先名】のように書く。
- **選ぶ部分**：会社によって要る・要らないが分かれる節は、`<!-- if 共同利用=する -->` … `<!-- endif -->` で囲む。ひな形を直したら `go run ./cmd/ja-docgen -check` で確認する（CI でも実行する）。
- **作成者向けの注記**：行頭を「※」にする。
- **文体**：方針・公表文・書式は「です・ます」。規程・手順は「である」調（「〜する」「〜しなければならない」）。委託契約の覚書（33）は、取引先に読みやすいよう「です・ます」にしている。自社の契約書の書式に合わせて「である」調に直してもよい。
- **用語**：[訳語表](../glossary.md) に合わせる。代表的なもの：個人情報保護管理者、個人情報保護監査責任者、従業者、委託先、本人、開示等の請求等、是正処置、内部監査、マネジメントレビュー、要配慮個人情報、個人関連情報、仮名加工情報、匿名加工情報、保有個人データ。
- **文書の冒頭**：次の表を置く。

  | 項目 | 内容 |
  | --- | --- |
  | 文書番号 | 【文書番号】 |
  | 版 | 第 1 版 |
  | 制定日 | 【制定日】 |
  | 承認者 | 【代表者氏名】 |
  | 対応する J 番号 | J.x.x、… |

- **文書の末尾**：「改訂履歴」の表（版、改訂日、改訂内容、承認者）を置く。
- **規程間の参照**：ほかの規程は「『安全管理規程』（12）」のように、文書名と上の一覧の番号で示す。
- **記録**：規程・手順で「記録する」と書く場合は、どこに記録するか（このシステムの「処理活動」「リスク」「本人からの請求」「監査」「指摘事項」「取引先」「タスク」「ドキュメント」など、または【記録の保管場所】）を書く。
