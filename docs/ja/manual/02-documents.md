# 2. 文書編

Pマークの方針・規程・公表文・書式の 18 本を、会社の情報を入れた完成版として作り、OpenGRC に登録して、フレームワークと内部統制に紐付けます。そのあと、承認・公開と従業者の署名を行います。

| 手順 | 作業 | 場所 |
| --- | --- | --- |
| 2.1 | 設定ファイルを書く | 手元のパソコン |
| 2.2 | 完成版を作る | 手元のパソコン |
| 2.3 | OpenGRC に登録し、紐付ける | 手元のパソコン → OpenGRC |
| 2.4 | 内容を確認し、承認・公開する | 管理画面 |
| 2.5 | 従業者の署名を集める | 管理画面 → 従業員ページ |
| 2.6 | 改訂する | 管理画面 |

文書の一覧と内容は [ひな形の README](../templates/README.md) を見てください。

## 準備：作業用のフォルダ

自社の値を入れた設定ファイルと完成版は社外秘です。**このリポジトリの外**に、社内用のフォルダ（社内の非公開のリポジトリなど）を用意して、そこに置きます。生成ツールは、このリポジトリの中の設定ファイルや出力先を受け付けません。誤ってコミットしないためです。

以下の例では、このリポジトリの隣に `社内/` というフォルダを作ったものとします。

```text
作業用のフォルダ/
├── opengrc/   … このリポジトリ（コマンドはここで実行する）
└── 社内/      … 自社の設定ファイルと完成版（非公開）
```

## 2.1 設定ファイルを書く

1. 設定例をコピーします。

   ```sh
   cp docs/ja/templates/config.example.yaml ../社内/自社.yaml
   ```

2. `../社内/自社.yaml` を、自社の値に書き換えます。項目の一覧と既定値は [variables.md](../templates/variables.md) にあります。

| 区分 | 書くこと | 注意 |
| --- | --- | --- |
| `会社:` | 会社名、代表者、所在地、問合せ窓口、電話番号、メールアドレス、公表ページの URL、管理区域、取扱区域 | 公表ページは、01・20・21 を載せるウェブページです。まだなくても、用意する予定の URL を書いておけます |
| `体制:` | 個人情報保護管理者、監査責任者、代行者、情報システム担当者 | 監査責任者は管理者と別の人にします。代行者も、管理者・監査責任者とは別の人にします |
| `文書:` | 制定日（`2026-11-01` の形式） | 改訂日を省くと制定日と同じになります |
| `運用:` | 保存期間、頻度、期限など | 既定値から変えるものだけを書きます。審査機関への事故の報告先は、申請先（JIPDEC 又は指定審査機関）の案内で確認して書きます |
| `選択:` | 第三者提供、共同利用、外国への提供・保管、Cookie などの外部送信、匿名加工情報、認定個人情報保護団体、手数料、事務所の仕切り | 選んだ答えに合う節だけが完成版に残ります |
| `利用目的:` | 誰の情報を（区分）、何に使うか（目的） | 従業者の情報も必ず入れます。他社から預かって扱う情報は `保有個人データ: false` を付けます |
| `外部送信:` | Cookie などで外部に送る情報 | `Cookieなどの外部送信: あり` の場合だけ書きます |

### 利用目的の書き方

`利用目的:` は、完成版の「個人情報の取扱いについて」（20）と「保有個人データに関する事項の公表」（21）の表になります。

```yaml
利用目的:
  - 区分: お客様・取引先の担当者
    個人情報: 氏名、会社名、部署、役職、連絡先
    目的:
      - 契約の締結と履行
      - 請求と支払
  - 区分: 従業者と退職者
    個人情報: 氏名、住所、連絡先、人事・給与に関する情報
    目的:
      - 人事・労務・給与の管理
      - 法令に基づく手続き
  - 区分: 委託を受けて取り扱う個人情報
    個人情報: 委託元との契約で定めるもの
    目的:
      - 委託元との契約で定める業務の遂行
    保有個人データ: false
```

- 区分は、個人情報管理台帳（第 3 章）の区分とそろえます。
- 問合せ窓口（メールやフォーム）があれば「お問い合わせをいただいた方」、採用をしていれば「採用に応募された方」も入れます。
- 健康診断の結果などの要配慮個人情報を扱う場合は、その項目も書きます。

## 2.2 完成版を作る

```sh
go run ./cmd/ja-docgen -config ../社内/自社.yaml -out ../社内/完成版
```

- 「18 documents written to …」と表示されれば完了です。
- 入力が足りない項目があると、完成版を出さずに、どの文書のどこが足りないかを表示します。設定ファイルを直して、もう一度実行します。
- 完成版は Markdown です。社内のリポジトリで版を管理しておくと、設定を変えたときに、どこが変わったかを差分で確かめられます。

## 2.3 OpenGRC に登録し、紐付ける

完成版を「下書き」として OpenGRC に登録し、次の 2 つに紐付けます。

- **フレームワークの項目**：各文書の冒頭の「対応する J 番号」に書いた項目
- **内部統制**：その J 番号に紐付いている内部統制。ただし、漏えい等の緊急時対応手順（15）は「緊急事態への準備と漏えい等への対応」だけに紐付けます

### 手順

1. 操作用のコマンド `prb` を用意します（初回だけ）。

   ```sh
   go build -o bin/prb ./cmd/prb
   ```

2. OpenGRC にログインします。表示された URL をブラウザで開き、コードを入れて承認します。

   ```sh
   bin/prb auth login --hostname https://（OpenGRC の URL）
   ```

3. 組織の ID を確かめます。管理画面で組織を開いたときの、アドレスバーの URL に含まれる ID です。
4. まず、何をするかを表示だけして確かめます。

   ```sh
   node scripts/ja-docs/sync.mjs --org （組織の ID） --docs ../社内/完成版
   ```

   18 本それぞれについて、登録するか（`create`）、すでにあるか（`exists`）と、紐付ける項目の数が表示されます。

5. 問題がなければ、`--apply` を付けて実行します。

   ```sh
   node scripts/ja-docs/sync.mjs --org （組織の ID） --docs ../社内/完成版 --apply
   ```

- 何度実行しても、文書や紐付けが重複することはありません。同じタイトルの文書があれば作り直さず、紐付けだけを足します。
- すでに登録した文書の内容は更新しません。内容を変えるときは、2.6 の方法で行います。

### 文書の種類と公開範囲

| 文書 | 種類 | 公開範囲 |
| --- | --- | --- |
| 01 個人情報保護方針、20 個人情報の取扱いについて、21 保有個人データに関する事項の公表 | 方針 | 公開 |
| 02 個人情報保護方針（内部向け） | 方針 | 社内 |
| 10〜17 規程・手順 | 手順 | 社内 |
| 30〜35 書式 | テンプレート | 社内 |

### 確認

- 「ドキュメント」に 18 本が下書きとして並びます。
- 「フレームワーク」の Pマークの各項目と、「内部統制」の各項目を開くと、紐付いた文書が表示されます。

## 2.4 内容を確認し、承認・公開する

1. 「ドキュメント」で文書を開き、内容が自社の実態に合っているかを確かめます。本文は画面で直接直せます。直した内容は自動で下書きに保存されます。
2. 「公開」を押します。「ドキュメントを公開」の画面が開きます。
3. 「変更履歴」に、この版の内容を書きます（例：「制定」）。
4. 「承認者」に代表者を加え、「承認を依頼」を押します。承認者にメールが届き、全員が承認するとメジャー版として公開されます。

- 方針と規程は、代表者の承認を受けてから公開します。Pマークの審査では、承認の記録が確認されます。
- 承認を依頼している間は、本文を編集できません。

## 2.5 従業者の署名を集める

内部向けの方針（02）と規程（10〜17）は、全従業者に周知し、確認の署名を受けます。

1. 「ドキュメント」で文書を選び、「署名を依頼」を押します。
2. 署名を求める従業者を選びます。
3. 従業者は、従業員ページで文書を読み、署名します。

署名の記録が、方針・規程を周知したことの証跡になります。署名していない人には、個別に周知します。

## 2.6 改訂する

### 公開する前

下書きの文書は、次のどちらかで直します。

- 画面で本文を直接直す
- 設定ファイルを直して完成版を作り直し、「ドキュメント」でその文書を削除してから、2.3 の `sync.mjs --apply` を実行する（新しい内容で登録され、紐付けもやり直されます）

### 公開した後

公開した文書は、版の履歴と承認の記録を残すため、削除せずに書き換えます。

1. 文書を開いて本文を書き換えます。新しい下書きとして保存され、公開中の版は変わりません。
2. 「公開」を押し、「変更履歴」に変更の内容を書きます。
3. 変更の大きさに応じて選びます。

   | 選択 | 使う場面 |
   | --- | --- |
   | マイナー版として公開 | 誤字の修正など、内容が変わらないもの。承認は不要 |
   | 承認を依頼 | 規程の中身が変わるもの。承認されるとメジャー版として公開 |

4. 書き換えをやめるときは「下書きを削除」で、最後に公開した版に戻します。

- 署名を受けた方針・規程の中身を変えたときは、改めて署名を依頼します。
- 会社の情報や選択（管理者の交代、手数料の有無など）が変わったときは、設定ファイルを直して完成版を作り直し、差分を見ながら画面に反映すると、漏れを防げます。

次は「3. 年間の運用編」（準備中）で、台帳、リスク評価、教育、内部監査を進めます。
