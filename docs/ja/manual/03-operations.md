# 3. 年間の運用編

Pマークの運用で 1 年を通して回す作業を、OpenGRC の画面で進める手順です。この章は機能ができた順に書き足していきます。

| 手順 | 作業 | 状態 |
| --- | --- | --- |
| 3.1 | 個人情報管理台帳を作り、Excel で出力する | 公開 |
| 3.2 | リスクアセスメントを行い、リスク分析表を Excel で出力する | 公開 |
| 3.3 | 教育を計画し、受講記録を Excel で出力する | 公開 |
| 3.4 | 内部監査を行い、内部監査報告書を Excel で出力する | 公開 |
| 3.5 | マネジメントレビューと是正 | 準備中 |

## 3.1 個人情報管理台帳

個人情報管理台帳（以下「台帳」）は、OpenGRC の **処理活動** で管理します。1 つの業務（採用選考、問い合わせ対応など）を 1 件の処理活動として登録し、一覧を Excel の台帳として出力します。台帳に書く項目は、規程『個人情報保護マネジメントシステム規程』（ひな形 10）第14条で決めています。

### 台帳の項目と入力する場所

台帳の項目は、処理活動の画面の 2 か所に分かれています。上の **処理活動の項目** はもともとある項目、下の **個人情報管理台帳の項目** は、Pマークの台帳のために追加した項目です。

| 台帳の項目（Excel の列） | 画面の項目 | 場所 |
| --- | --- | --- |
| 業務の名称 | 名前 | 処理活動の項目 |
| 担当部門 | 担当部門 | 個人情報管理台帳の項目 |
| 個人情報の項目 | 個人情報の区分 | 処理活動の項目 |
| 要配慮個人情報 | 特別カテゴリーまたは犯罪関連データ | 処理活動の項目 |
| 本人の種類 | 本人の区分 | 処理活動の項目 |
| おおよその件数 | おおよその件数 | 個人情報管理台帳の項目 |
| 利用目的 | 目的 | 処理活動の項目 |
| 取得の方法 | 取得の方法 | 個人情報管理台帳の項目 |
| 保管の場所と媒体 | 保管の場所と媒体 | 個人情報管理台帳の項目 |
| アクセスできる人の範囲 | アクセスできる人の範囲 | 個人情報管理台帳の項目 |
| 保存期間 | 保存期間 | 処理活動の項目 |
| 廃棄の方法 | 廃棄の方法 | 個人情報管理台帳の項目 |
| 委託先 | 取引先（委託先として登録した取引先を選ぶ） | 処理活動の項目 |
| 第三者提供の相手 | 提供先 | 処理活動の項目 |
| 外国への移転 | 国際移転、移転時の保護措置 | 処理活動の項目 |
| 安全管理措置 | 安全管理措置 | 処理活動の項目 |
| 最終見直し日・次回見直し日 | 最終レビュー日・次回レビュー日 | 処理活動の項目 |

次の項目は GDPR（EU の法律）のための項目で、Pマークの台帳には出力しません。入力は必須のものがあるので、次のように選んでおきます。

- **法的根拠**：本人の同意を得て取得するものは「同意」、契約の履行に必要なものは「契約上の必要性」など、近いものを選ぶ
- **ロール**：自社が取得・利用する業務は「管理者」、他社から委託を受けて扱う業務は「処理者」
- **データ保護影響評価・移転影響評価**：通常は「不要」。リスク評価（3.2）で必要と判断したものだけ「必要」にする

「特別カテゴリーまたは犯罪関連データ」は GDPR の用語ですが、日本の個人情報保護法の **要配慮個人情報**（人種、信条、病歴、犯罪の経歴など）に当たるものがあれば「はい」を選びます。台帳には「あり・なし・可能性あり」と出力されます。

### 手順

1. 左のメニューの **処理活動** を開き、**処理活動を追加** で業務を 1 件ずつ登録します。洗い出しの方法は規程第14条1項のとおりです（部門ごとに、取得・利用・保管・提供・廃棄している個人情報を聞き取ります）。
2. 登録した処理活動を開き、上の項目を入力して **変更を保存** を押します。
3. 同じ画面の下にある **個人情報管理台帳の項目** に、担当部門・件数・取得の方法などを入力し、**台帳の項目を保存** を押します。2 つの保存ボタンは別々なので、両方押してください。
4. すべての業務を登録したら、処理活動の一覧に戻り、**台帳を出力（Excel）** を押します。`個人情報管理台帳_出力日.xlsx` がダウンロードされます。

入力のこつ：

- **おおよその件数** は「年間約 300 件」「約 1,200 件（2026 年 4 月時点）」のように、時点か期間がわかるように書きます。
- **保管の場所と媒体** は、システム名と紙の保管場所の両方を書きます（例：「採用管理システム、書庫A（施錠）」）。
- **アクセスできる人の範囲** は、人の名前ではなく役割で書きます（例：「人事部の採用担当者」）。

### 出力される Excel

- シートは 1 枚で、1 行目に表題、2 行目に組織名と出力日、4 行目に見出し、5 行目から業務が 1 行ずつ並びます。業務は名前の順です。
- A4 横・1 ページの幅に収まるように印刷の設定がしてあり、2 ページ目以降にも見出しが印刷されます。
- 空欄の項目は、入力が漏れている項目です。出力したら空欄がないか確認し、あれば画面で入力してから出力し直します。

審査で台帳を提出するときは、この Excel を使います。Excel で直接書き直した内容は OpenGRC に戻らないので、直すときは必ず画面で直してから出力し直してください。

### 見直し

台帳は、年 1 回以上と、業務の追加・変更・廃止があったときに見直します（規程第14条4項）。

1. 各処理活動を開き、内容が今の業務と合っているか確認して、必要なら直します。
2. **最終レビュー日** に見直した日、**次回レビュー日** に次の見直しの予定日を入れて保存します。
3. 台帳を出力し、見直しの記録として保存します（文書として登録する方法は第 2 章を参照）。

見直しの実施者は、出力した台帳に記入するか、マネジメントレビューの記録に残します。

### 使える人

| 役割 | できること |
| --- | --- |
| オーナー・管理者 | 処理活動と台帳の項目の登録・変更、台帳の出力 |
| 閲覧者 | 処理活動と台帳の項目の閲覧、台帳の出力 |

## 3.2 リスクアセスメントとリスク分析表

リスクアセスメントの結果は、OpenGRC の **リスク** に記録します。台帳（3.1）の業務ごとに、個人情報の各段階で起こりうるリスクを洗い出し、評価と対策を記録して、一覧を Excel のリスク分析表として出力します。進め方は、規程『個人情報保護マネジメントシステム規程』（ひな形 10）第16条（リスクアセスメント）と第17条（リスク対応）で決めています。

### リスク分析表の項目と入力する場所

| リスク分析表の項目（Excel の列） | 画面の項目 | 場所 |
| --- | --- | --- |
| 業務の名称、要配慮個人情報 | 処理活動の名前、特別カテゴリーまたは犯罪関連データ | 処理活動（3.1 で登録したもの） |
| リスクID | 参照ID（自動で付く） | リスクの一覧 |
| 段階 | 段階 | リスクの概要タブの **リスク分析表の項目** |
| 想定されるリスク | リスク名 | リスクの編集 |
| リスクの内容 | 説明 | リスクの編集 |
| 発生可能性・影響度・リスク値 | 初期リスクの発生可能性・影響度（リスク値は自動で計算） | リスクの編集 |
| 対応方針 | 対応方針（低減・受容・回避・移転） | リスクの編集 |
| 対策（内部統制） | 紐付けた内部統制の名前 | リスクの **内部統制** タブ |
| 残留リスクの発生可能性・影響度・残留リスク値 | 残留リスクの発生可能性・影響度 | リスクの編集 |
| 責任者 | オーナー | リスクの編集 |
| 備考 | メモ | リスクの編集 |

**段階** は、規程第16条の 5 つの段階（取得・入力、移送・送信、利用・加工、保管・バックアップ、消去・廃棄）から、そのリスクが起こる段階をすべて選びます。

### 手順

1. 3.1 の台帳をそろえておきます。リスク分析表の行は、台帳の業務（処理活動）が基になります。
2. 左のメニューの **リスク** を開き、**リスクを追加** で、洗い出したリスクを 1 件ずつ登録します。リスク名は「応募書類の誤送信」のように、何が起きるかがわかる名前にします。発生可能性と影響度は『リスク評価基準』に従って選びます。一般的なリスクの例（82 件）から選んで名前と説明を入れることもできます。画面が日本語のときは、日本語の例が表示されます。例は Pマークの個人情報のリスクに限らないので、名前と説明は自社の業務に合わせて書き直します。
3. 登録したリスクを開き、**概要** タブの下にある **リスク分析表の項目** で、段階と、対象の台帳（処理活動）を選んで **リスク分析表の項目を保存** を押します。同じリスクが複数の業務に当てはまるときは、業務をすべて選びます。
4. **内部統制** タブで、対策に当たる内部統制を紐付けます。紐付けた内部統制の名前が「対策」の列に出力されます。
5. 対策を決めたら、リスクを編集して **対応方針** と **残留リスク** を入力します。残留リスクを受容してよいかは、個人情報保護管理者が判断します（規程第17条2項）。
6. すべての業務のリスクを入力したら、リスクの一覧に戻り、**リスク分析表を出力（Excel）** を押します。`リスク分析表_出力日.xlsx` がダウンロードされます。

### 出力される Excel

- 台帳の業務とリスクの組み合わせごとに 1 行です。同じリスクを 2 つの業務に紐付けると、2 行になります。
- 業務は名前の順、同じ業務の中では段階の早いリスクから（取得・入力 → … → 消去・廃棄）、同じ段階なら参照IDの順に並びます。段階を選んでいないリスクは、その業務の最後に並びます。
- リスクを 1 件も紐付けていない業務は、「想定されるリスク」に **（リスク未登録）** と出力されます。リスクアセスメントの漏れなので、リスクを登録して紐付けてください。
- どの業務にも紐付けていないリスク（情報セキュリティ全般のリスクなど）は、リスク分析表には出力されません。
- 印刷の設定は台帳と同じです（A4 横・幅 1 ページ、見出しを各ページに印刷）。

台帳と同じく、Excel で直接書き直した内容は OpenGRC に戻りません。直すときは画面で直してから出力し直してください。

### 見直し

リスクアセスメントは、年 1 回以上と、業務・システム・委託先などを変えるときに行います（規程第16条3項）。台帳を見直したら（3.1）、新しい業務や変わった業務のリスクを見直し、リスク分析表を出力して記録として保存します。

### 使える人

| 役割 | できること |
| --- | --- |
| オーナー・管理者 | リスクとリスク分析表の項目の登録・変更、リスク分析表の出力 |
| 閲覧者 | リスクとリスク分析表の項目の閲覧、リスク分析表の出力 |

## 3.3 教育

Pマークでは、すべての従業者（役員、正社員、契約社員、パートタイマー、アルバイト、派遣社員）に年 1 回以上の教育を行い、その記録を残します。OpenGRC の **教育** に年度ごとの教育を登録し、受講者の受講状況と理解度テストの結果を記録して、教育実施記録を Excel で出力します。進め方は『教育規程』（ひな形 16）で決めています。

### 教育実施記録の項目と入力する場所

| 教育実施記録の項目（Excel の列） | 画面の項目 | 場所 |
| --- | --- | --- |
| 年度、教育の名前、種類、実施期間、方法、講師 | 同じ名前の項目 | 教育の追加・編集 |
| 氏名、部門 | メンバーの氏名と部門 | 受講者（メンバーから選ぶ） |
| 受講日、受講の確認 | 教材への署名の日（自動）、または手入力の受講日 | 受講者の表、受講者の **編集** |
| 点数、合否 | 点数、合否（合格点から自動で判定） | 受講者の **編集**（理解度テストありの教育だけ） |
| 状況 | 完了・テスト未実施・不合格・未受講（自動） | 受講者の表 |
| 備考 | 備考 | 受講者の **編集** |

**種類** は規程第5条の 4 種類（定期教育、新規入社者教育、役割別教育、臨時教育）から選びます。

### 受講の判定

- **署名で受講する場合**：受講者が、実施期間内に **すべての教材**（文書）に従業員ポータルで署名すると、受講済みになります。受講日は、最後に署名した日です。
- **署名を使わない場合**（集合研修など）：受講者の **編集** で受講日を入力すると、受講済みになります。手入力の受講日は署名より優先します。
- **理解度テストありの教育**：受講済みで、テストに合格すると **完了** です。点数を入力すると、合格点以上で合格になります。あとで点数や合格点を直すと、合否も直ります。合格点を決めていない教育や、点数と違う判定にしたいときは、合否を手で選びます。受講済みでテストの結果がないときは **テスト未実施**、不合格のときは **不合格** です。
- 受講日は、今日より後の日付は入力できません。
- 実施期間は、教育を追加したときのタイムゾーン（日本なら Asia/Tokyo）の日付で判定します。期間の前や後の署名は数えません。

署名は、同じ文書の同じ版（メジャーバージョン）には 1 回しかできません。去年の教育で署名した規程を今年も教材にすると、署名が期間外のため数えられず、新しく署名を依頼することもできません。この場合、受講者の表の「署名した教材」に **期間外に署名済みの教材があります** と表示されます。毎年の教育では、年度の教材（「2026年度 個人情報保護教育 資料」など）を新しい文書として作るか、規程を改訂してメジャーバージョンを上げてから教材にしてください。

### 手順

1. 教材にする文書を作り、公開しておきます（第 2 章）。公開していない文書には署名を依頼できません。
2. 左のメニューの **ガバナンス** → **教育** を開き、**教育を追加** で教育を登録します。年度、教育の名前、種類、方法、実施期間、講師、内容を入力します。理解度テストを行う教育は **理解度テスト** を「あり」にし、合格点を入力します（『教育規程』第8条の合格基準）。
3. 登録した教育を開き、**教材** の **教材を選ぶ** で教材の文書を選んで保存します。教材は 1 つの教育に 20 件まで、受講者は 2,000 人まで登録できます。
4. **受講者を追加** で受講者を選びます。**全員を選ぶ** で、契約が終了していないメンバー全員を選べます。派遣社員やアルバイトも、事前に従業員の役割で招待しておきます（第 1 章）。
5. **署名を依頼** を押すと、まだ受講していない受講者に教材の署名が依頼されます。教材の最新の版が公開されていないと、どの教材を公開すればよいかがエラーで表示されます。契約が終了した人と無効にしたメンバーには依頼しません。受講者には依頼のメールが届き、従業員ポータルの **署名** で教材を読んで署名します。
6. 集合研修の場合は、受講者の **編集** で受講日を入力します。理解度テストを行ったら、点数を入力します。
7. 受講者の表の上で状況を **未受講** などに絞り込むと、未受講者の一覧になります。部門責任者に伝えて、期限までに受講させます（規程第9条）。
8. 実施期間が終わったら、教育の一覧で年度を選び、**教育実施記録を出力（Excel）** を押します。`教育実施記録_年度_出力日.xlsx` がダウンロードされます。年度で **すべての年度** を選ぶと、すべての教育を出力します。

### 出力される Excel

- 教育と受講者の組み合わせごとに 1 行です。教育は年度、開始日、名前の順に並びます。
- 受講者を 1 人も登録していない教育は、「氏名」に **（受講者未登録）** と出力されます。
- 印刷の設定は台帳と同じです（A4 横・幅 1 ページ、見出しを各ページに印刷）。

台帳と同じく、Excel で直接書き直した内容は OpenGRC に戻りません。

### 記録の保存

教育の記録は、審査で求められる証跡です。消えないように、次の操作はできません。

- 受講済み（署名または手入力）か、テストの点数・合否が入っている受講者を **外す** こと。誤って追加した、記録のない受講者は外せます。
- 記録のある受講者がいる教育を **削除** すること。

受講日や点数の入力を誤ったときは、受講者の **編集** で直します。保存期間は『個人情報保護マネジメントシステム規程』（ひな形 10）の記録の一覧で決めた期間です。

### 新規入社者教育

新しく業務に就く人には、業務で個人情報を取り扱う前に教育を行います（規程第10条）。年度ごとに **新規入社者教育** を 1 つ登録し（実施期間は年度の初めから終わりまで）、入社した人をそのつど受講者に追加して、署名を依頼します。

### 使える人

| 役割 | できること |
| --- | --- |
| オーナー・管理者 | 教育の登録・変更・削除、教材と受講者の設定、署名の依頼、受講記録の入力、教育実施記録の出力 |
| 閲覧者・監査人 | 教育と受講記録の閲覧、教育実施記録の出力 |
| 従業員 | 従業員ポータルで教材を読んで署名する（教育の画面は見られません） |

## 3.4 内部監査

Pマークでは、年 1 回以上の内部監査で、規程どおりに運用されているかを確かめ、結果を監査報告書にまとめて代表者に報告します。OpenGRC の **監査** に監査ごとの記録を作り、見つかった問題を **指摘事項** に登録して紐付け、内部監査報告書を Excel で出力します。進め方は『内部監査規程』（ひな形 17）で決めています。

### 内部監査報告書の項目と入力する場所

報告書には、規程第8条で決めた事項が載ります。

| 内部監査報告書の項目（Excel） | 画面の項目 | 場所 |
| --- | --- | --- |
| 監査の名前、フレームワーク、監査日 | 名前、フレームワーク、監査開始日・監査終了日 | 監査の詳細（上の項目） |
| 監査の範囲、監査の基準 | 監査の範囲、監査の基準 | 監査の詳細の **内部監査報告書の項目** |
| 監査員 | 監査員（社内）、監査員（外部） | 同上 |
| 被監査部門 | 被監査部門 | 同上 |
| 総合的な所見 | 総合的な所見 | 同上 |
| 指摘事項の件数（分類ごと） | 紐付けた指摘事項から自動で数える | — |
| 指摘事項一覧：参照 ID、内容、原因、是正処置、担当者、期限、状態、有効性の確認 | 同じ名前の項目 | 指摘事項の詳細 |
| 指摘事項一覧：分類、根拠 | 分類、根拠 | 指摘事項の詳細の **内部監査の分類と根拠** |

**分類** は規程第7条の 3 つ（不適合、観察事項、改善の機会）です。指摘事項の **種別** から自動で決まり、必要なときだけ選び直します。

| 指摘事項の種別 | 報告書の分類（選ばなかったとき） |
| --- | --- |
| 重大な不適合 | 不適合（重大） |
| 軽微な不適合 | 不適合 |
| 観察事項 | 観察事項 |
| 例外 | 分類なし（「その他」として数える） |

**改善の機会** は種別にないので、観察事項などで登録してから、分類で **改善の機会** を選びます。

### 手順

1. 年間の監査計画を作り、代表者の承認を得ます（規程第3条）。承認した計画書は、監査ごとの **監査** に添付するか、文書として登録します。
2. 左のメニューの **ガバナンス** → **監査** で監査を追加します。フレームワークは Pマーク（JIS Q 15001）を選び、名前（「2026 年度 内部監査」など）を付けます。
3. 監査を開き、監査開始日・監査終了日を入れます。下の **内部監査報告書の項目** に、監査の範囲（対象の規程・J 番号）と監査の基準を入れます。監査の基準には、最初は「JIS Q 15001:2023、当社の規程、法令等」が入っています。
4. **監査員（社内）** でメンバーから監査員を選びます。外部の専門家に頼んだときは、**監査員（外部）** に氏名を 1 行に 1 人ずつ入れます。**被監査部門** も 1 行に 1 つずつ入れます。
5. **報告書の項目を保存** を押します。社内の監査員の部門（メンバーの部門）が被監査部門と同じだと、**監査員が自分の部門を監査しています** と表示されます。監査員は自分の部門を監査できない（規程第4条）ので、別の監査員に替えます。保存はできるので、部門の名前の書き方が違うだけのときはそのままでかまいません。
6. 監査で見つかった問題は、**指摘事項** に登録し、監査に紐付けます（規程第8条）。指摘事項の詳細の **内部監査の分類と根拠** で、分類と根拠（「J.7 安全管理措置」など）を入れて保存します。紐付けた指摘事項は、監査の詳細の **この監査の指摘事項** に並びます。
7. 監査が終わったら、**総合的な所見**（PMS の適合性と有効性）を入れて保存し、**監査報告書を出力（Excel）** を押します。`内部監査報告書_出力日.xlsx` がダウンロードされます。
8. 報告書を確認して代表者に報告します。最終版は PDF にして、監査の詳細の **監査報告書** にアップロードします（アップロードできるのは PDF だけです）。写しを個人情報保護管理者に渡します。
9. 是正処置の内容、期限、有効性の確認は、指摘事項に記録し、完了したら状態を **完了** にします（規程第9条）。

### 出力される Excel

- シートは 2 枚です。**監査概要** は項目と内容の 2 列、**指摘事項一覧** は指摘事項ごとに 1 行で、参照 ID の順に並びます。
- 指摘事項を 1 件も紐付けていない監査は、指摘事項一覧に **（指摘事項なし）** と出力されます。
- 印刷の設定は台帳と同じです（A4 横・幅 1 ページ、見出しを各ページに印刷）。

台帳と同じく、Excel で直接書き直した内容は OpenGRC に戻りません。

### 使える人

| 役割 | できること |
| --- | --- |
| オーナー・管理者 | 監査と指摘事項の登録・変更、報告書の項目と分類・根拠の入力、監査報告書の出力 |
| 閲覧者・監査人 | 報告書の項目と指摘事項の閲覧、監査報告書の出力 |

指摘事項は最大 100 件まで監査の詳細に表示されます。報告書の Excel には、紐付けたすべての指摘事項が出力されます。
